# ADR-0023

Status: Accepted

## Context

Athena contains several mature application capabilities including:

- Retrieval
- Evidence and citation services
- Workspace intelligence
- AI provider services
- Conversation services
- Document viewing services

The Assistant foundation already provides:

- AssistantCapability
- CapabilityRegistry
- ActionRegistry
- Workflow planning
- Validation boundaries
- Controlled execution boundaries

A review was performed to determine whether Athena requires a new
global tool or plugin framework.

The review found that Athena already has clear service boundaries and
that introducing a separate execution-oriented capability framework would
duplicate existing architecture.

## Decision

Athena will introduce capability contracts only as a lightweight
description layer over existing capabilities.

Capability contracts will describe:

- capability purpose
- service boundary
- supported inputs
- produced outputs
- evidence requirements
- validation requirements

Capability contracts will not:

- replace existing services
- introduce a new execution framework
- duplicate Assistant actions
- create autonomous tool behaviour

Existing services remain the implementation boundary.

## Architecture Direction

Current:

Service
    |
Assistant Adapter
    |
Assistant Capability
    |
Action
    |
Workflow


Future:

Capability Contract
    |
Existing Service
    |
Optional Assistant Integration
    |
Validated Result

## Consequences

Positive:

- preserves existing architecture
- improves capability discoverability
- supports future reuse
- avoids premature framework creation

Negative:

- capability contracts must remain aligned with real services

## Future Direction

A21 will incrementally document and formalize existing Athena
capabilities.

Future tool or plugin work must build on capability contracts rather
than introduce parallel systems.

Autonomous execution frameworks remain deferred.
