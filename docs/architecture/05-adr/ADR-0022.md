# ADR-0022

Status: Accepted

## Context

Athena contains multiple mature capability areas including:

- Assistant capabilities
- Retrieval services
- Knowledge services
- Evidence and citation services
- Workspace services
- AI provider services

The Assistant foundation already provides:

- CapabilityRegistry
- ActionRegistry
- Workflow planning
- Validation boundaries
- Controlled execution boundaries

A review was performed to determine whether Athena requires a separate
tool framework.

The review found that creating a parallel tool architecture would
duplicate existing concepts.

## Decision

Athena will evolve existing capability and action concepts into reusable
capability contracts.

No separate tool registry architecture will be introduced.

Capabilities remain the primary abstraction for Athena functionality.

Actions represent controlled operations associated with capabilities.

Future capability contracts may describe:

- purpose
- inputs
- outputs
- evidence requirements
- validation requirements
- execution policies
- service bindings

These additions will be introduced only when justified by concrete use
cases.

## Consequences

Positive:

- preserves existing architecture
- avoids duplicate frameworks
- improves reuse of Athena capabilities
- supports future Assistant growth

Negative:

- future features must align with capability boundaries

## Future Direction

A21 will formalize capability contracts incrementally.

A22 will mature Assistant workflows using these existing foundations.

Autonomous agent frameworks and unrestricted tool execution remain
deferred.
